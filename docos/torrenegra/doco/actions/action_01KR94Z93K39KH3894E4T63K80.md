not atomic. If `copyFile` (or any subsequent write) throws after `mkdir`,
the Doco directory exists in a half-created state and blocks retries
with "Doco already exists at …". I asked whether to ship the
atomic-create fix (try/catch + rmdir on failure, OR check inside the
existence check whether `doco.yaml` is present) and the user hasn't
answered yet. Captured as a separate backlog Action
